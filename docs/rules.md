# 대회 규칙 정리 (공식 규정 숙지본)

> 원문: 대회 규정 §1 데이터셋 개요, §2 평가, §3 모델 학습·추론 및 외부 자원, §4 제출 규칙 (2026-07-03~04 전달받음). 전 섹션 확보 완료.

## §1. 데이터셋 개요

- 과제: 뒤섞인 4개 비디오 프레임 + 텍스트 설명(Sentence) → 원본 시간 순서 복원.
- train / test 구분 제공, 검증셋 없음 → train에서 직접 분할 (`src/data/split.py`).
- 프레임 일부는 생성형 AI로 생성, 캡션도 사람/AI 혼재.
- **train에 정제되지 않은 데이터 포함이 공식 명시**: ① 프레임만으로 정답을 하나로 특정 불가(→ `No_ordering`의 근거), ② 텍스트와 무관한 프레임(검은 프레임 등).
- **효과적인 전처리 적용 여부가 본선 평가 기준에 포함** → `reports/preprocessing.md`가 본선 대비 산출물.
- 정답 인코딩 예시: 원본 a,b,c,d / 입력 a,d,b,c → `[1,4,2,3]` = **rank 인코딩 공식 확정** (상세: `docs/label_encoding.md`).

## §2. 평가 (2026-07-04 확보 — Phase 0 블로커 해소)

- **지표: Exact Match Accuracy** — 제출 순서가 정답과 완전히 동일해야만 정답, 하나라도 다르면 오답 (부분 점수 없음).
- 예선 리더보드는 **테스트 데이터의 70%(Public)** 만으로 갱신. 예선 종료 후 전체(Public+Private)로 최종 성능 산정.
- 예선 종료 후 상위팀 대상 **코드 검증 + 보고서 검토** 수행.
- 성능 수준에 따라 **외부 데이터셋 기반 별도 성능 평가**가 진행될 수 있음 → train 분포 특이점(파일명 등 아티팩트)에 과적합하지 말고 의미 기반 일반화 유지.

### 시사점
- 부분 점수가 없으므로 Kendall τ류 보조지표는 내부 분석용일 뿐, **의사결정은 val EM**으로.
- Public 70% ≈ 573샘플 → 1샘플 ≈ 0.17%p. LB 노이즈 있으므로 val(953) 기준 판단이 더 안정적.
- EM 최적 디코딩 = 순열 단위 argmax (mode 투표/전수 스코어링이 Borda보다 지표 정합).

## §3. 학습·추론 및 외부 자원

### 3.1 환경
- Python. **인터넷 차단 로컬 환경(CPU 또는 GPU)에서 실행 가능해야 함** → 모델 가중치·토크나이저 전부 사전 다운로드, 코드에 네트워크 호출 금지.

### 3.2 외부 상용 API
- 학습·추론에는 **전면 금지** (ChatGPT, Gemini, Grok 등).
- **데이터 전처리 목적에 한해 허용, 총비용 ≤ ₩30,000.** 사용 시 발표 자료에 방식·실험 결과·비용 명시 의무. 초과 판정 시 실격.
- ⚠️ CoT 학습 타깃을 API로 생성하는 것이 "전처리"인지 "생성형 데이터 변형"(3.3 금지)인지 경계 모호 → 사용하려면 **Kaggle Discussion에 사전 문의 필수**. 현재 파이프라인은 규칙 기반 분해(`caption_events.py`)라 API 불필요.

### 3.3 데이터·모델
- **외부 데이터 금지** — 제공된 train만 사용.
- 오픈소스 모델 허용, 단 **가중치 공개일 ≤ 2026-05-31**.
- **앙상블 전면 금지**: 서로 다른 모델 조합은 물론, **동일 모델을 데이터 분할로 여러 개 파인튜닝해 결과를 조합하는 것도 금지** → k-fold 체크포인트 평균/투표 불가, 최종 제출은 단일 체크포인트.
- **데이터 증강 허용** (제공 데이터 활용) — 프레임 순서 재셔플 증강은 합법. 단 **생성형 모델을 이용한 데이터 생성/변형 금지** (디퓨전 이미지 증강, LLM 캡션 재작성 증강 등 불가).
- **경량화 허용**: Quantization, LoRA 등.
- **추론 전략 자유**: CoT, Multi-turn, **TTA 명시적 허용** — 24h 제한 내라면. TTA는 앙상블로 간주되지 않음.
- 테스트셋 전체 추론이 검증 환경에서 **24시간 이내** 완료되어야 함.

### 3.4 데이터 누수 (실격 사유)
- 평가 데이터 정보를 학습에 활용 금지: 수작업 라벨링 금지, **test 특성 분석을 전처리·모델 설계에 반영하는 것도 금지**.
- → **작업 수칙: 모든 EDA·전처리 설계·하이퍼파라미터 결정은 train에서만 도출.** test에는 동일 파이프라인을 추론 시 기계적으로 적용만 한다.

### 3.5 규칙 위반
- 위반 시 실격 가능. **리더보드 상위 참가자는 코드·결과 재현성 검증 요청 대상** → 시드 고정, 환경 명세, 재현 스크립트 유지 필요.

## §4. 제출 규칙

- **제출 1일 2회 제한** → 리더보드 프로빙 최소화, val 지표로 의사결정.
- 최종 모델 실행 환경: **RTX 3090 1개 (VRAM 24GB)**.
- 서버 사양: AMD EPYC 7502 ×2 (64코어), RAM 512GB, driver 550.54.15, **CUDA 12.4**.

## 전략 시사점 (확정 전략 기준)

1. **VLM SFT 단일 모델 전략과 전부 정합**: LoRA/QLoRA 허용 + 24GB VRAM → Qwen2.5-VL 3B급은 여유, 7B급도 QLoRA 학습·bf16 추론 가능. UNORDERABLE CoT 분기도 "추론 표현 방식 자유"로 합법.
2. **TTA가 합법적 최대 레버**: 동일 모델에 프레임 입력 순서 순열을 여러 개 넣고 예측 rank를 집계(Borda 등)하는 permutation-TTA 가능. 24h 예산 내 TTA 횟수 설계 필요 (819샘플 × N회).
3. **순열 재셔플 학습 증강 합법** — 라벨 변환은 `src/utils/permutation.py`만 사용.
4. **k-fold 앙상블 불가** → 분할은 검증용으로만, 최종은 전체 train 재학습 단일 체크포인트가 정석.
5. **오프라인 실행**: HF 가중치 사전 캐시, `HF_HUB_OFFLINE=1`로 로컬 리허설.
6. **train-only 원칙**: 레터박스 비율(21.5%) 등 기존 통계는 전부 train 기반이라 문제없음. 앞으로도 test EDA 금지.
7. 제출 2회/일 → 제출 전 val exact match + 순열 유효성 assert로 사전 검증 철저히.
