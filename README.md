# SNU AI Challenge — 비디오 프레임 순서 맞추기

> **처음 이 프로젝트를 받는 분을 위한 안내서입니다.**
> 전문 용어는 최대한 풀어서 설명했습니다. 순서대로 읽으면 "무엇을 만드는지 → 어떻게 돌아가는지 → 내가 뭘 실행하면 되는지"까지 한 번에 이해할 수 있습니다.

---

## 1. 이 프로젝트는 뭘 하나요? (한 문장 요약)

**뒤죽박죽 섞인 비디오 장면 4장을, 원래 시간 순서대로 다시 정렬하는 AI를 만드는 대회입니다.**

영화 필름 4컷을 누가 섞어 놓았다고 생각하면 됩니다. 우리 AI는 그 4컷을 보고 "원래는 이 순서였겠구나" 하고 맞혀야 합니다. 힌트로 **그 영상을 설명하는 영어 문장(캡션)** 이 같이 주어집니다.

---

## 2. 정확히 어떤 입력을 받고, 무엇을 내놓나요?

### 입력 (문제)
- **이미지 4장**: 한 영상에서 뽑은 장면 4개. 순서가 뒤섞여 있습니다. (파일 컬럼 이름: `Input_1` ~ `Input_4`)
- **캡션 1개**: 그 영상을 시간 순서대로 서술한 영어 문장.
  - 예: *"A girl hula hoops indoors, **then** the scene shifts outdoors, **and finally** players swim."*
  - `then`, `finally`, `before`, `after` 같은 **순서를 나타내는 연결어**가 들어있어서, 문장을 쪼개면 "사건이 일어난 순서"를 알 수 있습니다.

### 출력 (정답)
각 입력 이미지가 **시간순으로 몇 번째인지**를 숫자로 적은 목록입니다.

| | 뜻 |
|---|---|
| 원본 영상 순서 | a, b, c, d (a가 제일 먼저) |
| 우리가 받은(섞인) 입력 | a, d, b, c |
| **정답** | `[1, 4, 2, 3]` |

읽는 법: **"입력 1번(a)은 시간순 1등, 입력 2번(d)은 4등, 입력 3번(b)은 2등, 입력 4번(c)은 3등"**.

> ⚠️ 이 방향(입력 위치 → 시간 순위, "rank 인코딩")은 헷갈리기 쉬워서 대회 규칙과 주최 측 코드로 **확정**해 두었습니다. 자세한 근거는 [docs/label_encoding.md](docs/label_encoding.md). 순서 변환은 **반드시** [src/utils/permutation.py](src/utils/permutation.py) 의 함수만 쓰세요. (직접 손으로 바꾸면 방향 버그가 납니다.)

### 채점 방식
- **완전 일치(Exact Match)**: 4장 순서가 **하나도 안 틀리고 전부 맞아야** 1점. 3장만 맞으면 0점입니다. (부분 점수 없음)
- 그래서 우리는 항상 "완전히 맞힌 비율(EM)" 하나만 보고 판단합니다.

### "섞이지 않은" 문제도 있어요 (`No_ordering`)
학습 데이터의 약 **15.5%** 는 애초에 섞지 않은 영상입니다. 이런 샘플의 정답은 항상 `[1, 2, 3, 4]` (그대로)입니다.
- 처음엔 이걸 "순서를 정할 수 없는 이상한 샘플"로 오해했는데, **실은 그냥 주최 측이 안 섞은 정상 영상**이라는 걸 나중에 확인했습니다. (자세한 사정은 [docs/findings.md](docs/findings.md))

## 3. 대회 규칙 — 왜 파이프라인이 이렇게 생겼는지

이 규칙들이 설계의 대부분을 결정했습니다. ([docs/rules.md](docs/rules.md) 전문)

| 규칙 | 우리에게 미치는 영향 |
|---|---|
| **인터넷 없는 환경에서 실행** | 모델 파일을 미리 받아두고, 코드에서 네트워크 호출 금지 |
| **여러 모델을 섞으면 안 됨(앙상블 금지)** | 최종 제출은 **딱 한 개의 모델**로만. 이게 가장 중요한 제약 |
| **외부 데이터 학습 금지** | 준 데이터 안에서만 학습. 그래서 "프레임을 다시 섞어 학습량을 늘리는" 방법이 핵심 |
| **외부 유료 API는 학습·추론에 금지** (전처리에 한해 3만 원까지만 허용) | AI가 실제로 추론할 땐 우리 로컬 모델만 사용 |
| **테스트 전체 추론을 24시간 안에** | RTX 3090 GPU 1대에서. 그래서 "몇 번 반복 예측할지" 예산 계산이 필요 |
| CoT·TTA(뒤에 설명) 같은 추론 기법은 **허용** | 한 모델 안에서 여러 번 물어보고 다수결 내는 건 합법 |

> **핵심**: "여러 모델 금지"라서, 우리는 **단 하나의 똑똑한 모델**을 잘 학습시키고, 그 하나에게 **여러 각도로 여러 번 물어봐서 다수결**을 내는 전략을 씁니다.

## 4. 전체 그림 — 데이터가 어떻게 흘러가나요?

```
 [원본 데이터]                    [준비]                       [학습]
 이미지 4장 + 캡션  ──▶  1. train/검증 나누기      ──▶   4. 하나의 VLM 모델을
 (train.csv)            2. 검은 띠 잘라내기               LoRA로 미세조정
                        3. 학습용 문제-정답 생성           (Qwen VL 계열)
                                                              │
                                                              ▼
 [제출]                          [추론]                    [완성된 모델]
 submission.csv   ◀──  7. 유효성 검사 후 저장  ◀──  5. 같은 문제를 여러 각도로
 (819개 정답)          6. 여러 답을 다수결로 집계        여러 번 예측 (TTA)
```

**한 줄 정리**: 데이터를 정리하고 → 프레임을 이리저리 섞어가며 모델을 학습시키고 → 시험 볼 땐 한 문제를 여러 번(각도를 바꿔서) 풀게 한 뒤 → 가장 많이 나온 답을 최종 정답으로 냅니다.

## 6. 단계별 자세한 설명

### 단계 1 — 데이터 불러오고 나누기 (`src/data/`)
- [loader.py](src/data/loader.py): CSV를 읽어서 각 문제의 이미지 4장 경로를 붙여줍니다.
- [split.py](src/data/split.py): 학습용(train)과 성능 확인용(validation, 줄여서 "val")을 **90:10** 으로 나눕니다.
  - 이때 그냥 무작위로 나누지 않고, **캡션이 비슷한 문제끼리는 같은 쪽으로** 묶습니다. 안 그러면 거의 같은 문제가 학습과 검증 양쪽에 들어가서, 실제보다 성능이 부풀려 보이는 "커닝" 효과가 생기기 때문입니다.
  - 결과물: `outputs/split.csv`

### 단계 2 — 전처리 (`src/preprocess/`)
데이터를 깨끗하게 다듬고, 학습 재료를 늘리는 단계입니다. **실제로 쓰는 것**과 **실험만 해본 것**이 섞여 있습니다.

**실제로 파이프라인에 쓰는 것:**
- [frame_quality.py](src/preprocess/frame_quality.py): 영상 위아래에 생기는 **검은 띠(레터박스)를 잘라냅니다.** 전체의 21.5%가 해당되고, 효과가 확인된 유일한 정제 단계입니다.
- [caption_events.py](src/preprocess/caption_events.py): 캡션 문장을 `then`/`finally` 같은 연결어 기준으로 **사건 단위로 쪼갭니다.** ("A했다, 그다음 B했다" → [A, B])
- [caption_augment.py](src/preprocess/caption_augment.py): 같은 뜻의 캡션을 **연결어만 바꿔서 여러 버전으로** 만듭니다. 모델이 특정 표현에만 익숙해지지 않게 하는 학습 재료입니다.
- [hard_cases.py](src/preprocess/hard_cases.py) / [hard_weights.py](src/preprocess/hard_weights.py): 모델이 **자주 틀리는 어려운 문제**를 찾아서, 그런 문제를 학습 때 더 자주 보여주도록 가중치를 매깁니다. (가중치는 전부 모델 자신의 예측 기반 — 외부 API 무관)

**실험만 하고 최종 파이프라인엔 안 쓰는 것 (참고용):**
- [no_ordering.py](src/preprocess/no_ordering.py), [semantic_features.py](src/preprocess/semantic_features.py): "이 샘플이 섞인 건지 아닌지"를 픽셀·이미지 특징만으로 맞혀보려 했지만 **효과가 없어서** 분석용으로만 남겨둠.

### 단계 3 — 학습용 문제-정답 만들기 (`src/train/`)
모델에게 보여줄 "문제와 모범 답안"을 만드는 단계입니다.
- [targets.py](src/train/targets.py): 모범 답안의 **형식(스타일)** 을 정합니다. 여러 형식이 있습니다:
  - `plain`: `Order: ... / Answer: [순서]` — 가장 단순한 최신 형식.
  - `mid`, `short`, `cot` 등 이전 실험 형식들도 있습니다. (`cot` = "생각의 사슬", 답을 바로 내지 않고 단계적으로 추론 과정을 적는 방식)
- **순열 증강(핵심!)**: 같은 문제라도 **매번 프레임 순서를 다르게 섞어서** 보여주고, 정답도 그에 맞게 바꿔줍니다. 이렇게 하면 "첫 번째 자리에 온 게 항상 시작"이라는 잘못된 습관을 모델이 못 들이고, 진짜로 내용을 보고 순서를 판단하게 됩니다. 외부 데이터를 못 쓰는 상황에서 **학습량을 공짜로 늘리는 가장 중요한 방법**입니다.
- [vl_dataset.py](src/train/vl_dataset.py): 위 재료들을 모아 실제 학습에 넣을 수 있는 형태로 만드는 데이터셋 클래스입니다.

### 단계 4 — 모델 학습 (`configs/`, `cloud/`, `colab/`)
- **모델**: 이미지와 글을 함께 이해하는 **VLM(Vision-Language Model, 시각-언어 모델)** 을 씁니다. Qwen VL 계열입니다.
  - 현재 설정 파일: [configs/sft_qwen.yaml](configs/sft_qwen.yaml) 은 **Qwen2.5-VL-7B**, [configs/sft_qwen8b.yaml](configs/sft_qwen8b.yaml) 은 더 큰 **Qwen3-VL-8B** 입니다. (지금까지 최고 성적은 8B 모델)
- **LoRA 미세조정**: 70억 개짜리 거대 모델을 통째로 다시 학습시키는 건 너무 무겁습니다. 그래서 **모델 대부분은 얼려두고, 아주 작은 부품(어댑터)만 새로 학습**합니다. 이게 LoRA입니다. 메모리·시간이 크게 절약됩니다.
- **어디서 돌리나**: 우리 로컬 PC는 GPU가 없어서(CPU 전용) **학습·추론은 클라우드 GPU**에서 합니다.
  - Colab (A100/L4): [colab/qwen_vl_colab.ipynb](colab/qwen_vl_colab.ipynb)
  - RunPod: [cloud/](cloud/) 폴더 + [docs/runpod.md](docs/runpod.md)
- 주요 설정값(7B 기준): 3 epoch, 유효 배치 16, 학습률 0.0001, 시드 42 고정(재현성).
- 학습이 끝나면 LoRA 어댑터를 본체와 **합쳐서(merge)** 완성 모델을 만듭니다.

### 단계 5 & 6 — 추론과 다수결 (`src/infer/`)
시험을 보는 단계입니다. **한 문제를 여러 번, 각도를 바꿔가며** 풀게 하는 게 핵심입니다.
- [predict.py](src/infer/predict.py): **TTA(Test-Time Augmentation, 테스트 때 증강)** 를 수행합니다.
  - 쉽게 말해: 같은 4장을 **여러 방식으로 다시 섞어서** 모델에게 여러 번 물어봅니다. (예: 8번) 자리 순서에 따른 편향을 씻어내려는 겁니다.
  - 각 예측 결과(원본 텍스트)를 파일에 그대로 저장합니다.
- [aggregate.py](src/infer/aggregate.py): 위에서 나온 여러 답을 **다수결**로 모아 하나로 정합니다.
  - 각 예측을 원래 좌표로 되돌린 뒤, **가장 많이 나온 순서**를 최종 답으로 채택합니다.
  - 만약 표가 너무 갈려서 "합의가 안 된" 경우엔 안전하게 `[1,2,3,4]`(그대로)로 둡니다.
- (선택/대안) [ll_score.py](src/infer/ll_score.py), [fuse.py](src/infer/fuse.py): 24가지 가능한 순서를 모델이 각각 얼마나 "그럴듯하게 여기는지" 점수를 매겨 고르는 **다른 방식의 예측**입니다. 실험 결과 기본 다수결 방식이 더 나아서, 이 둘은 **보조/실험용**으로 남아 있습니다.

### 단계 7 — 제출 파일 만들기 (`src/infer/submission.py`)
- [submission.py](src/infer/submission.py): 최종 답을 `submission.csv` 로 저장하기 전에 **검사**합니다.
  - 819개 문제 답이 다 있는지, 모든 답이 {1,2,3,4}를 정확히 한 번씩 쓴 올바른 순서인지 확인합니다. 하나라도 이상하면 멈춥니다.
- [budget_check.py](src/infer/budget_check.py): 전체 추론이 **24시간 규칙**을 넘지 않는지 미리 시간을 재봅니다.

### 성능 측정 (`src/eval/`)
- [em.py](src/eval/em.py): **EM(완전 일치 비율)** 을 계산합니다. 우리의 유일한 판단 기준입니다.
  - 판단은 항상 test가 아니라 **검증셋(val)** 으로 합니다. (제출 횟수가 하루 2번으로 제한되고, 규칙상 test를 분석에 쓰면 안 되기 때문)

## 7. 그래서 나는 뭘 실행하면 되나요? (실전 순서)

아래는 **원본 데이터 → 학습된 모델 → 제출 파일**까지의 전체 순서입니다. 실제 명령은 Colab 노트북([colab/qwen_vl_colab.ipynb](colab/qwen_vl_colab.ipynb)) 셀에 정리되어 있으니, 처음이면 노트북을 위에서부터 따라가는 걸 추천합니다.

```bash
# 0) 데이터·모델 경로 확인 (configs/paths.yaml)

# 1) 학습/검증 나누기
python -m src.data.split                 # → outputs/split.csv

# 2) 학습용 문제-정답(jsonl) 만들기
python -m src.train.cot_target           # → outputs/sft_train.jsonl, sft_val.jsonl

# 3) (선택) 어려운 문제 찾기 + 캡션 증강

# 4) 학습 (GPU 필요 — Colab/RunPod)
#    먼저 소규모 smoke 테스트로 잘 돌아가는지 확인 후 본 학습
#    끝나면 LoRA를 본체와 merge

# 5) 검증셋으로 리허설 (여기서 성능 확인)
#    predict.py (--split train --fold val --tta 8) → aggregate.py → eval.em
#    이전 기록과 EM 비교해서 나아졌는지 판단

# 6) 진짜 test 추론 → 제출 파일
#    predict.py (--split test --tta 8) → aggregate.py (--submission outputs/submission.csv)
```

> **중요**: 추론할 때 쓰는 형식(`--style`)은 **학습할 때 쓴 형식과 반드시 같아야** 합니다. (예: `plain`으로 학습했으면 추론도 `plain`)

## 8. 꼭 알아둘 용어 (쉬운 풀이)

| 용어 | 쉬운 뜻 |
|---|---|
| **VLM** | 이미지와 글을 함께 이해하는 AI 모델 (Vision-Language Model) |
| **LoRA / 미세조정(SFT)** | 거대한 모델 전체를 다시 학습하는 대신, 작은 부품만 얹어서 우리 문제에 맞게 살짝 조정하는 방법 |
| **순열(permutation)** | 4장의 순서를 나열한 것. 예: `[1,4,2,3]` |
| **순열 증강** | 학습 때 프레임 순서를 매번 다르게 섞어 데이터를 불리는 것 |
| **TTA** | 시험 볼 때도 같은 문제를 여러 각도로 여러 번 풀게 해서 다수결로 정하는 것 |
| **다수결(vote) 집계** | 여러 예측 중 가장 많이 나온 답을 최종 답으로 고르는 것 |
| **EM (Exact Match)** | 4장 순서가 하나도 안 틀리고 다 맞아야 정답으로 세는 채점 방식 |
| **val (검증셋)** | 학습에 안 쓰고 남겨둔 데이터. 성능을 미리 재보는 용도 |
| **LB (리더보드)** | 대회 순위표. test로 채점되며 하루 제출 2회 제한 |
| **No_ordering** | 애초에 안 섞은 정상 영상. 정답은 항상 `[1,2,3,4]` |
| **앙상블** | 여러 모델을 조합하는 것 — 이 대회에선 **금지** |

## 9. 두 개의 트랙 (Track A vs Track B)

프로젝트엔 접근법이 두 갈래 있었습니다.

- **Track B = 지금의 메인 모델**: 위에서 설명한 VLM(Qwen VL) 미세조정 전체가 여기 해당합니다. **실제 제출은 전부 Track B**입니다.
- **Track A ([src/track_a/](src/track_a/)) = 구버전/분석용**: 이미지 특징만 뽑아 작은 모델로 순서를 맞혀보던 초기 실험입니다. 가볍게 CPU에서 돌아가서 "전처리가 효과 있나?" 같은 걸 빠르게 확인하는 **분석 도구**로 남겨두었고, 성능이 낮아 **최종 제출에는 쓰지 않습니다.** (규칙상 A와 B를 섞는 것도 앙상블이라 금지)

## 10. 현재 상태와 주의사항

- **지금까지 최고 성적**: 리더보드 EM 약 **0.88** (Qwen3-VL-8B + TTA). (1등은 약 0.93)
- **진짜 병목**: "섞인 문제를 실제로 정확한 순서로 푸는 능력". 여기를 올리는 게 점수 향상의 핵심입니다.
- **판단은 항상 val EM으로**: 제출은 하루 2번뿐이고 test를 분석에 쓰면 규칙 위반입니다. 모든 실험·결정은 train/val 안에서만 하세요.
- **순서 변환은 반드시 [src/utils/permutation.py](src/utils/permutation.py) 를 통해서만**: 손으로 바꾸면 방향 버그가 납니다. 관련 테스트가 [tests/](tests/) 에 있습니다.
